# Flag conventions (copied from Historical European Tags/tools/FLAG_NOTES.md)

## Sourcing

- Charges traced from WappenWiki SVGs produce CC BY-NC-SA 3.0 derivatives:
  every `gfx/flags/*.tga` except direct mod-to-mod copies is covered by the
  README Credits section — keep that statement true when adding flags,
  and keep the mod free.

- Beyond WappenWiki: attested non-heraldic regal designs trace their
  own sources with a named credit. Everything currently covered
  renders through the CK3-CoA pipeline below; the tools/fonts note
  (Amiri Bold) applies to nothing live.

## CK3-dynasty CoA pipeline (`tools/coaflags.py`)

Run per tag or for the whole `-ids` set:

    python3 tools/coaflags.py TAG ... [--save PATH]
    python3 tools/coaflags.py --all [--save PATH]

The tags carry CK3's own coat of arms for that 867 dynasty:

- **Sourcing order** (per tag, `ruler_coa`) — Patrum Scuta's authored
  `house_*`/dynasty blocks (its files load after the base game's
  in-game, so its rows win), then base game `90_dynasties.txt`, then a
  non-ironman CK3 save: the save's `coat_of_arms_manager_database`
  holds every CoA the engine generated. Preferred there is the
  **dynasty record**'s `coat_of_arms_id` (`key=<CK3 dynasty>` — what
  the dynasty and its members display) before the title entity's
  top-level id (a title may carry its own standalone design, which is
  wrong for ALG/SIQ: they now take save-dyn#20541/#23731). Random-
  template dynasties (ALG, MOR, MRW, SAW, SIQ, SNH, SRV, ZAB, ZIY,
  TRP, ...) have CK3 rolls with no authored block anywhere and
  unreproducible RNG (CK3's generation is not seed-stable) — a
  non-ironman 867 bookmark is the only faithful source. **The pinned
  source is `867 Save.ck3`** (a static 867 bookmark exported for this
  pipeline; newer saves are zips with one `gamestate` member —
  `_save_text` handles both). The database's ids are session-volatile:
  the same dynasty gets a different `coat_of_arms_id` after CK3
  resaves, so always re-resolve per run and never compare ids across
  save files. A ruler with no CK3 dynasty at all (fictional 867
  holders such as HDR's Shujah) still gets one generated by save
  time: `character_lookup` maps the game char to the save's internal
  index and the dynasty whose `dynasty_head` is that index carries
  the CoA (`save-char-dyn#`, the Shujahid precedent). `--all`
  covers every `-ids`-named tag except **PMS** (the Přemyslids keep
  their old WappenWiki flag by decision); arbitrary tags take
  positional arguments.
- **Engine model — copied from the shipped shaders** (`jomini/gfx/FX/
  coat_of_arms/coat_of_arms_pattern.fxh`, `..._textured_emblem.fxh`,
  the real math, not an inference):
  - Patterns: `lerp(Fallback, Color1, r)` then g/b toward Color2/3 —
    raw 0..1 channels, **no 2x saturate** (the earlier `min(2v,1)`
    reading is dead; r=255 on our pattern files makes the unknown
    Fallback unreachable).
  - Colored emblems: **base Color1 over the whole texture**, then
    `lerp(., Color2, g)`, `lerp(., Color3, r)`; channel **B is no
    colour slot at all** — it overlays as shading ink
    (`GetOverlay(..., b, 1.0)`, standard overlay: values ≤0.5 darken,
    ≥0.5 brighten; ~0.49 = neutral, which is what makes DLF's
    white-bladed sabre read on the white half). A colourN left
    undefined is the engine's zero-init: **sable** — confirmed
    in-game on DLF (its color1-only sabre blade renders sable; the
    earlier white default was wrong and is retired).
  - `mask={ r g b }` = the shader's `MaskColor` + `USE_PATTERN_MASK`:
    the emblem's alpha multiplies `saturate(cover1*mask.r`
    `+ cover2*mask.g + b*mask.b)` where the coverages derive from the
    pattern's raw channels (`cover1 = r-g-b`, `cover2 = g-b`, clamped
    0..1) — i.e. the emblem shows only on the pattern's colour1/2/3
    region(s) (SAW: the blue block on the field, the checky bend).
  - `ce_ordinary_*` textures are alpha-cut with B≈0.5 ink, so a
    color1-only def is exactly a base-fill silhouette.
  Instances carry position/scale/depth/rotation (degrees, full-canvas
  instance, `expand=False` — the textures carry their own cut corners).
  A **negative scale axis mirrors the instance** (the vertex shader
  flips the UV); the box still spans the magnitude. The parser must
  accept a leading minus on both position and scale — it once silently
  fell back to the 1.0 full-canvas default on negative scales and
  painted TIN/ZAM's mirrored twins as giant blobs.
- Emblem layers stack in file order, depth overrides. A no-instance
  emblem spans the full canvas centred. `textured_emblem` entries pass
  their artwork colours through unbaked; colourless `ce_empty` layers
  are dropped by the alpha compositing.
- **DDS reading** — most texture files are DXT1/DXT5/DX10 (Pillow
  handles them); 36+ are uncompressed 32-bit BGRA rasters (e.g.
  ce_block_02.dds) which decode by hand — Pillow cannot read
  uncompressed DDS and returns constant pixels for them. Do not "fix"
  the hand-decode back to an alpha-mask check on header offset 96: that
  offset is the *green* mask, and keying on it renders every block
  black.
- **Tincture canon, deterministic** — every CK3/PS colour name maps
  through an explicit `_SEMANTIC` row to one WappenWiki tincture
  (white/silver→argent, black→sable, blue→azure, red→gules,
  yellow→or, green→vert, purple→purpure, orange→orange, grey→cendrée,
  brown→brunatre, the PS shade rows like yellow_mid→or,
  brunatre_dark→senois, ...). There is no nearest-colour fallback: an
  unmapped colour name raises, and the fix is a hand-added row.
  Baked output clamps to [51,246] and composites on a #111111 underlay
  (EU4 flags are opaque), 24bpp BGR top-first TGA, desc 0x20.

## Canvas and charge position

- Flag canvas: 256x256 TGA.
- Charge flags (LUT, RAN, BOH, ABK): charge 176x210, pasted at (40,23)
  on the field colour.
- Charge proportions are immutable: only uniform scaling of the whole
  charge is permitted. Never stretch, squash, crop or reshape the artwork
  to fill the slot — fit it inside 176x210 keeping its aspect ratio, and
  centre the result on the (40,23) slot.
